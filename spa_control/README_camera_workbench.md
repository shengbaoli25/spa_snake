# SPA 相机测速与残差 PPO 实验工作台（保留版）

这是保留的相机测速与残差 PPO 实验程序，不含手柄功能。默认启动入口现为无相机的固定初始策略，见 `README.md`；本版供后续接回相机、验证单一地形速度跟踪时使用，尚未加入 Graph-Temporal SPA、预测头或跨构型适应。

## 启动

在项目根目录安装可选相机依赖后，显式启动本模块：

```powershell
& '.\spa_control\.venv\Scripts\python.exe' -m pip install -r '.\spa_control\requirements_camera.txt'
& '.\spa_control\.venv\Scripts\python.exe' -m spa_control.camera_workbench
```

相机工作台的离线演示使用 `python -m spa_control.camera_workbench --demo`。演示不访问机器人或相机，参数与结果仅验证软件流程，文件保存在 `runs/demo`；真实实验文件保存于 `runs/real`，两种模式不能互相载入策略。`start.bat` 与 `start_demo.bat` 启动的是无相机初始策略界面。

程序启动不自动连接或运动。使用新程序前，在旧 `Snake Robot Monitor` 中断开机器人控制连接，以免两个程序同时发指令。这里复用当前已使用的 TCP 9001 协议，不修改旧上位机或树莓派程序。

网络默认 `192.168.10.2:9001`，使用普通 TCP socket，走系统已配置的以太网路由，完全不使用 HTTP 代理。

## 首次配置

在“模型参数与通道”中设置：

| 设置 | 含义 |
|---|---|
| 四路通道 | 结构顺序对应的 `M1…M6` 中四个不同通道，默认 `1,2,3,4` |
| 前进方向 | 默认 `−1,+1,−1,+1`，沿用旧上位机前四路的交替方向；可以整体或逐路修改 |
| 标称指令 | 当前共享配置默认 300，必须为整数；是控制器指令单位，不是自行认定的 rpm |
| 指令上限 / 残差上限 | 当前共享配置默认 500 / 5，最终整数输出也受这两个上限约束；共享默认值不能代替实机允许范围的确认 |
| 外径 D / 导程角 β | 旧方案参考值 80 mm / 17°；β 从圆周方向量起，需要核对当前实物 |
| 实测导程 | 可直接填每转轴向前进距离，单位 mm/rev，优先于 D/β |
| 传动比 G | 转子转数 / 螺旋转数，必须填实际值 |
| rpm/指令 或标定表 | 填经验证的比例，或两列逗号分隔、严格递增的指令与转子 rpm；标定表优先，不进行外推 |
| 电流限值 | CAN 反馈电流原始量，默认 7000 只是候选值，须核对本机阈值；并非 A 或 Nm |
| 目标速度 | 空白时由标称指令计算；也可输入固定目标 m/s |

核对参数后勾选确认，再点“更新预览”，会显示导程、转子转速、理论速度以及六路完整指令。参数可保存/读取 JSON；读取后需重新核对实机设置。

运动学关系：

```text
L = π · D · tan(β)                 [m/rev]
n_motor = g_cal(q_nom)             [rpm]
n_helix = n_motor / G              [rpm]
v_theory = n_helix · L / 60         [m/s]
```

四个同构螺旋以相同标称转速配合前进，理论速度不乘以电机个数。这个关系是理想无滑移推进参考，真实地形的滑移通过相机测量。当前实现使用四电机共用的几何/速度标定，适用于同构驱动；各电机不同标定留待下一版。

## 全局相机测速

参考源码：桌面 `snakerobot_rl/pc_tools/global_camera_speed_core.py` 与 `global_camera_speed_gui.py`。

两种可直接使用的接法：

1. **直接 RGB 相机**：关闭原测速软件的相机连接，选择相机编号与标定 JSON，点击“连接测速”，待画面出现后拖框选择静止机器人的头部。相机连接期间不驱动电机。
2. **读取原测速实时 CSV**：在原测速软件里打开相机、完成跟踪并开始记录，然后在新程序选择当前正在写入的 CSV。无需修改原测速软件；不要选历史 CSV。

默认标定位置为 `Desktop/global_camera_calibration.json`，请使用当前相机与场地实际标定的文件。`left/right` 选择跟踪框的头部前沿，不改变轨道坐标正方向。相机位置/焦距改变时先用原测速软件重新标定；分辨率与标定不符时拒绝测速。

保留原有方法：CSRT 头部框 → 前沿参考点 → 分段轨道投影 → 0.06 s 位置低通 → 0.30 s 尾窗线性拟合速度。前三帧且跨度至少 0.20 s 才产生有效速度。丢失或过时数据不会变成零速度奖励。滤波本身存在时延；日志保留采样和接收时间用于后续检查。RGB时间为本机取帧时间，尚无相机硬件曝光时间同步。

`camera.py` 另提供本机 UDP 接收类，默认 127.0.0.1:9870，供后续集成；这不是旧测速软件已有的发布接口。UDP JSON 需 `timestamp_monotonic_s, position_m, velocity_mps, tracking_ok`，必须与本机 `time.monotonic()` 同时基。

## 一条轨迹如何执行

“标准前进·基线”：所有残差为零。

“残差 PPO·训练”：从当前策略采样四维动作，轨迹结束发送停止后，使用这条新轨迹更新 PPO；中止轨迹不更新。

“冻结策略·测试”：使用当前 Actor 的确定性均值，不采样探索、不更新。初始策略均值严格为零，因此未训练的确定性策略等于标准前进。

```text
Δq_j = residual_limit × tanh(z_j)
command[channel_j] = sign_j × clip(q_nom + Δq_j, 0, q_max)
非激活通道 = 0
```

整数协议下量化后也不允许突破残差上限。小于 1 指令单位的补偿可能被量化为零。

主要奖励遵循当前单地形验证要求：

```text
error = v_target − v_camera
reward_raw = −abs(error)
reward_ppo = reward_raw / fixed_speed_scale
```

默认固定尺度 0.05 m/s，动作幅值/变化惩罚均为 0，可配置。不能把有符号差值直接最大化，否则会奖励某一方向的偏差。目标只由标称指令或用户固定值确定，不随残差后的指令上升。

策略输入 17 维：按结构顺序的四组 `[转速、反馈电流raw、标称指令、上次实际残差]`，加目标速度；使用固定量程归一化。全局相机实际速度不进入 Actor，只用于训练奖励和评价。Actor/Critic 为各自 32×32 的小型 MLP，纯 NumPy PPO，包含 tanh 高斯采样、GAE、clip、Adam 和 KL 提前停止。采集策略版本与概率严格校验，旧轨迹不能混入新的 PPO 比值。

程序一次只运行一条轨迹，默认 12 s、10 Hz。结束后人工复位，再点击下一条；不会自动串行执行 180 次运动。界面计数标注“本次会话”，重开后的总量以保存的 summary.json 为准。

## 50 / 100 / 30 实验

1. 在同一地形、同一几何标定、相同标称转速、相同相机和起始位置下，完成 50 次标准前进记录。
2. 从零残差策略开始完成 100 次 PPO 训练，每次仅使用当前策略新采集轨迹；记录中止与故障，不能冒充有效成功试验。
3. 保持训练后的同一策略，完成 30 次冻结策略测试。
4. 比较速度 MAE、峰值电流、动作变化与中止率；保留逐次学习曲线。100 次训练是实验预算，不保证算法必然改善。每组相同标称指令和目标，若地形随重复试验改变，补做交错的基线复测以识别地形/电池漂移。

每条试验目录包含 `config.json`、`camera_metadata.json`、`metadata.json`、`policy_config.json`、`steps.csv`、`summary.json` 和开始前的 `policy_before.npz`。训练记录另含 `rollout.npz`，保存 obs/raw action/log probability/value/reward/terminal/version；成功更新时保存 `policy_after.npz`。中止的 rollout 标记 `used_for_update=false`，不计入有效次数。载入策略时核对输入输出维度、结构映射和量程以及真机/演示来源。

## 停止行为及验证范围

急停按钮、Escape、窗口失焦、相机/遥测失效、过流、界面心跳失效、程序关闭都会请求停止。控制线程与急停共享锁，防止急停后的排队动作再次下发；通信线程独立检查短时指令租约，超时发送 STOP 并锁存故障，须断开重连。

网络已经断开或进程被强杀时，上位机无法保证 STOP 到达 C 板。因此当前程序只记录停止命令写入是否成功，不宣称电机已物理停止；下位机的通信看门狗和物理急停仍需按当前已烧录版本确认。旧串口固件的 2 s 看门狗不能证明当前 TCP 桥接固件的行为。当前没有标定堵转判据或在线验证控制 ACK 的机制。

已做纯离线、localhost TCP 和真实 Tk 窗口验证，没有代用户驱动电机，也未验证真机训练收益。
