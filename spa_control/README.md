# SPA 四电机初始策略上位机

当前版本支持单电机调试与四电机固定初始策略：无相机、无手柄、PPO 关闭、残差始终为 0。用于先检查每路方向、转速反馈和电流，不需要填写螺旋几何或传动比。

## 启动和运行

双击本目录 `start.bat`。`start_demo.bat` 仅显示离线模拟，不连接机器人。也可在项目根目录运行：

```powershell
& '.\spa_control\.venv\Scripts\python.exe' -m spa_control.app
```

程序启动不会自动连接或运动。先断开其他上位机的控制连接，在本程序连接机器人、核对通道映射和六路指令预览，再点击需要的运行按钮。默认以 10 Hz 刷新命令，到时发送停止；每次开始由操作者点击。

网络默认 `192.168.10.2:9001`，使用直接 TCP socket，按系统配置的以太网路由通信，不使用 HTTP 代理。

已对照原 `snake_robot_monitor.py` 核实，当前程序发送相同的六路整数协议和末尾单个换行符，例如 `CTRL SPEED M1=-300 M2=300 M3=0 M4=0 M5=0 M6=0\n`；停止为 `CTRL STOP\n`，这里 `\n` 表示实际换行字节。原固定速度模式每 500 ms 重发一次（2 Hz），本程序默认每 100 ms（10 Hz）。点击“原版重发 2 Hz”仅将刷新频率改为 2 Hz，不会连接或启动电机。

连接状态分别显示 TCP 连接与电机反馈就绪数量。只有对应通道收到完整、及时且未过流的转速/电流反馈后，“单独运行”才可用；四路全部就绪才能一起运行。连接后没有数据时不自动启动，也不把缺失反馈当成零。“通信诊断”页显示本次接收字节数、行数、最近数据时间及原始消息；TCP 已连接但一直为 0 字节时，需检查树莓派转发服务和 C 板到树莓派的数据链路。

通信诊断还显示 PC 成功写入命令的次数、发送间隔、写入耗时和 STOP 次数。这些统计表示 PC socket 写入情况，并非 C 板或 CAN 电机的执行 ACK；是否实际转动、转速是否稳定仍需结合及时的电机反馈判断。

## 逐路调试与四路运行

四行电机设置分别包含通道、方向下拉框“正转 + / 反转 −”和独立速度，速度默认均为 300。每一路的方向和速度可以分别设置。

点击某行的“单独运行”时，只给该通道发送所选方向和速度，其余五路恒为 0，默认运行 3 秒。等待本次停止后才能切换下一路，不能同时启动第二个单电机试验。“急停”和“停止全部”始终可用。

确认每一路设置后，点击“四路一起运行”，程序按四行各自的速度、方向和通道映射下发，默认运行 12 秒。要一次设置相同速度，在共同速度输入框填值，再点“应用到四路”；之后仍可单独调整某一路。

“保存初始策略”将四路速度、方向、通道映射及试验设置保存为 JSON；载入时恢复这些设置。旧 JSON 若只有共同速度，则用该值填充四路，兼容原有参数文件。

## 默认策略与接线预设

默认按当前四电机交替前进要求设置，结构顺序对应 `M1,M2,M3,M4`，方向为 `[-1,+1,-1,+1]`，共同指令幅值为 300，指令上限为 500：

```text
M1 = -300    M2 = +300    M3 = -300    M4 = +300
M5 =    0    M6 =    0
```

可选预设“附件旧接线（M1–M4）”使用相同四通道，方向改为 `[-1,+1,+1,+1]`，指令为 `[-300,+300,+300,+300,0,0]`。它来自用户提供的旧 `go_forward()` 参考：完整六路方向为 `[-,+,+,+,+,-]`。这个预设不改变程序的交替默认；按当前实体接线选择，通道和方向均可单独修改。

300 是现有 `CTRL SPEED` 协议的整数指令值，不能据此宣称已经标定为 300 rpm。实际转速应结合 CAN 转子速度反馈检查；若需要物理 rpm，须核实电调反馈单位和指令到转子转速的换算。界面与日志中的反馈速度来自 CAN，反馈电流为原始值 raw，不是 A 或 Nm。

## 日志与停止

每次运行保存到 `runs/real/`；演示写入 `runs/demo/`。四路试验使用 `baseline_no_camera` 模式，单电机调试使用 `single_motor` 模式并独立计数，不计入四路基线次数。目录含 `config.json`、`metadata.json`、`steps.csv`、`summary.json`，记录对应通道、指令、反馈转速、电流、时间戳、结束或中止原因。

这两种模式按绝对控制周期发送命令，错过的时隙不集中补发。日志交由后台有界队列写入，控制线程不逐步等待磁盘刷新；队列满或写入失败会中止试验。结束或异常时先请求 STOP，再收尾日志，日志失败的试验不能标为完成。汇总保留实际链路错误及停机前后通信诊断，以区分过流、发送中断和停止写入失败。

这些记录没有相机速度、速度奖励或 PPO 训练数据，不更新策略。没有机器人实际前进速度反馈时，不能用电机转速替代地面推进速度来证明强化学习改善。后续相机测速和 PPO 工作台保留在 `camera_workbench.py`，使用方法见 `README_camera_workbench.md`。

急停按钮、Escape、窗口失焦、遥测过时、过流、界面心跳超时或关闭窗口都会请求停止。独立指令租约超时后发送 `CTRL STOP` 并锁存，拒绝后续非零指令；必须断开后重新连接，点击停止或改变刷新频率不会解除锁定。日志区分“停止已写入通信链路”与“电机已物理停下”；通信中断后不能保证 STOP 到达，下位机看门狗需以当前固件为准。

## 依赖和验证

默认界面仅依赖 NumPy 与 Python 自带 Tkinter，安装清单为 `requirements.txt`。相机版另用 `requirements_camera.txt`，增加 Pillow 和 OpenCV。

这些修改用于改善 PC 端命令调度并保留排查证据，不能据此认定真机卡顿已经解决。

```powershell
& '.\spa_control\.venv\Scripts\python.exe' -m unittest discover -s spa_control/tests -v
```
